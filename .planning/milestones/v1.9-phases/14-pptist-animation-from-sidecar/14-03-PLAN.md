# Plan 14-03 — Defaults propagation, stderr diagnostics, end-to-end tests

## Objective

Finalise Phase 14 by layering three things on top of the Wave 2 bridge:

1. **Defaults propagation** (D-21 + ANIM-DEFAULTS-01) — when a sidecar row omits a field, fall back through `entry.animation?` → `sidecar.defaults.animation?` → hardcoded `0.45s`/`'after-previous'`/`undefined`. The resolution chain lives in `injectAnimations()`; the test fixtures prove every tier.

2. **Stderr diagnostics** (D-23 + ANIM-DIAG-01) — at the end of `convertDir()`, print a single summary line to `process.stderr` (counts of slides / PPTAnimations / extensions fields / unmapped effects) plus a `WARN:` block listing every group whose `elId` could not be resolved.

3. **End-to-end coverage** against `exampels/202610131101001/` (the 13-covered / 7-uncovered distribution) plus CLI smoke tests. The E2E suite is the deliverable that proves the 17 v1.9 requirements actually run on real fixtures.

## Context

Wave 2 shipped a complete but incomplete bridge: `injectAnimations` ignored `defaults`, the diagnostic accumulator was collected but never printed, and no end-to-end test exercised the real `exampels/202610131101001/` fixture. Wave 3 closes those gaps. The mapper and injector modules are mature; the new work here is (a) resolution-chain logic inside the existing `injectAnimations` body, (b) a single new line in `convertDir()` that calls `printDiagnostics(diagnostics)`, and (c) three test files that pin the behavior down.

This plan owns the observability seam (ANIM-DIAG-01) and the ANIM-DEFAULTS-01 logic; both are one-way observable behaviors and need the `checkpoint: decision` reversibility gate before the action. Plan 03's reversibility watchpoint is **D-22** in particular — adding defaults propagation tempts you to also auto-fill empty slides; the test must explicitly forbid that.
