# Plan: text-measurement-opt

## 目标

优化 text 元素转换速度，将 text 测量从串行改为缓存+并行。

## 当前行为（性能问题）

- 每个 text 元素单独调用 `measureTextElement`
- 每次调用都 `new Resvg(svgString)` + `getBBox()`
- 51 个元素串行执行，每个 ~200ms，总计 ~10s

## 目标行为

- 相同文本/字体参数只测量一次（缓存）
- 多个 text 元素并行测量

## 实现步骤

### 1. 添加测量缓存 — `src/text-measurer.ts`

在 module 级添加 `Map<string, ...>` 缓存，按以下 key 缓存测量结果：

```typescript
// 缓存 key: content|fontFamily|fontSize|fontWeight|fontStyle|letterSpacing|textAnchor|x
const measurementCache = new Map<string, { width: number; height: number; y: number }>()
```

修改 `measureTextElement`，先查缓存，命中则直接返回；未命中则测量后写入缓存。

### 2. 并行测量多个 text 元素 — `src/transformer/transform-to-pptel.ts`

在 `transformToPPTElement` 的 `walk` 函数中，收集所有 text 元素的测量需求，等 `walk` 完成后并行执行测量，最后回填结果。

**改动点**：
- `walk` 中遇到 text 元素时，不直接调用 `measureTextElement`，而是将 `(element, measurementInput, index)` 存入数组
- `walk` 完成后，用 `Promise.all` 并行测量所有 text
- 将测量结果按 index 回填到对应元素

**注意**：并行度不需要无限，限制并发量为 8（`Promise.all` 配合 `map(..., { concurrency: 8 })` 或手动分批）

## 验收标准

1. 日志显示 `[文本测量] measureTextBBox` 调用次数 << text 元素数量（缓存命中）
2. 51 个元素的 SVG 转换总耗时明显下降（目标：减少 50%+）
3. 现有测试全部通过

## 风险

- 缓存 key 冲突：严格使用完整参数构造 key，避免不同内容撞上
- 并行度太高可能导致 WASM 竞争：限制 concurrency = 8
