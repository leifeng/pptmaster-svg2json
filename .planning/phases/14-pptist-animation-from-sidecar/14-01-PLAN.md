# Plan 14-01 — Foundation: id injection, type extensions, CLI parent-dir, convertDir() shell

## Objective

Lay the structural plumbing for Phase 14: declare `nanoid` as a direct dependency, extend the `PPTAnimation` interface with the `extensions` provenance field, inject the new id-naming policy (D-05~09) into the transformer's `walk()` + path-merge call site, add the new `convertDir()` public function and CLI parent-dir dispatch — but emit NO `slide.animations[]` or `turningMode` content yet. After this plan, a user can run `svg2json <parent-dir>/202610131101001` and get 20 well-formed `.svg.json` files (one per SVG) with element ids conforming to D-05~09, ready for Plan 02 to layer the animations on top.

## Context

The svg2json project currently ships a single-SVG→single-Slide converter (`src/index.ts` `convert()` + `src/cli.ts` main). Phase 14 graduates it to a multi-slide demo assembler. This foundation plan owns all the irreversible cross-module seams: the new public API surface (`convertDir`), the new id policy (one-way — once consumers see ids they anchor to them), the type-system extension (`extensions` field — interface one-way), and the CLI mode dispatch (parent-dir vs recursive). No animation injection happens here — Plan 02 wires that on top.

Upstream: this plan is Wave 1 and depends on nothing (Wave 1 must runnable alone).
Downstream: Plan 02 consumes the new id-naming, the `convertDir` shell, and the `extensions` field; Plan 03 rounds out defaults + diagnostics + E2E.
