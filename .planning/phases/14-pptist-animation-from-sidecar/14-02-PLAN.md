# Plan 14-02 — Mapping: mappers/animation.ts + animation-injector + sidecar wire-up

## Objective

Build the pure-function mapper module (`src/mappers/animation.ts`) that translates three-side keys to PPTist effect strings, trigger modes, and transitions; build the sidecar bridge (`src/animation-injector.ts`) that consumes those mappings to assemble `slide.animations[]`; wire the new bridge into `convertDir()` in `src/index.ts`; add unit tests for each mapping function. Animation injection becomes real in this plan; defaults propagation and stderr diagnostics are Plan 03's job (but the diagnostic accumulator type lives here).

## Context

Wave 1 prepared all the structural seams: `convertDir()` shell, `convertDirOptions.animationsPath?`, the `extensions` field on `PPTAnimation`, and the interface types in `src/animation-types.ts`. Wave 2 fills in the actual translation logic — pure functions in the mapper, side-effectful glue in the injector, and the wire-up inside `convertDir()`.

This plan owns all mapping decisions (D-14~20) and the sidecar-bridge logic. It does NOT touch the transformer (Wave 1 already shipped id injection), and it does NOT add defaults propagation or stderr diagnostics to the final summary — Plan 03 wires those.

### Task 2: sidecar bridge — `src/animation-injector.ts`

The injector consumes the mapper functions, walks the sidecar entry for one slide, resolves `elId` from the existing `slide.elements` groupId, and returns a new slide object with `animations[]` and `turningMode` populated. The function is pure-ish: it returns a new `Slide` and accumulates diagnostics into a caller-provided object (so `convertDir()` can sum across slides).

</read_first>
