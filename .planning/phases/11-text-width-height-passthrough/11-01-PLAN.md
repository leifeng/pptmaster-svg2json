# 11-01-PLAN — text-width-height-passthrough

## 目标

让 `transformElement` 在处理 SVG `<text>` 时，如果元素同时声明了 `width` 和 `height` 属性，跳过 resvg-js 测量，按 `scaleX` / `scaleY` 缩放后直接作为 `textWidth` / `textHeight` 输出。

## 背景

`src/transformer/transform-to-pptel.ts` 的 `case 'text'`（line 1474 附近）目前无条件调用 `measureTextElement(input)` 来获取文本 bbox。当 SVG 源文件自带 `width` / `height` 时，这是一笔可以省掉的开销（resvg-js WASM 初始化 + 渲染耗时），而且对于已声明尺寸的元素，作者的意图本身就是"使用此尺寸"。

当前实现 line 1598 已经有 `const fixedHeight = !!element.attrs.height` 用作 PPTist `fixedHeight` 字段——说明 height 已经被识别，但 width / height 的具体数值没有进入 PPTElement 的 `width` / `height`。

## 改动范围

只动 `case 'text'` 顶部的一段测量逻辑。其他 case（rect / circle / image 等）的 width / height 处理保持原样。

<action>
在 `src/transformer/transform-to-pptel.ts` 的 `case 'text':` 内（紧接 `const { html: contentHtml, text: content } = buildTextContentFromElement(element, fontSize, scaleY)` 之后）插入如下块：

```ts
// Phase 11: 直通 SVG text 自带的 width / height 属性，跳过 resvg-js 测量
// 仅当 width 和 height 都解析为正数时生效；其他情况继续走测量路径
const rawTextWidth = element.attrs.width
const rawTextHeight = element.attrs.height
const parsedTextWidth = rawTextWidth !== undefined ? parseFloat(String(rawTextWidth)) : NaN
const parsedTextHeight = rawTextHeight !== undefined ? parseFloat(String(rawTextHeight)) : NaN
let usePassthrough = Number.isFinite(parsedTextWidth) && parsedTextWidth > 0
  && Number.isFinite(parsedTextHeight) && parsedTextHeight > 0
if (usePassthrough) {
  textWidth = parsedTextWidth * scaleX + TEXT_WIDTH_SAFETY_MARGIN
  textHeight = parsedTextHeight * scaleY
  // 没有 measured.y，使用 FALLBACK_ASCENT_RATIO 与 catch 块保持一致
  textTop = transformed.top - fontSize * FALLBACK_ASCENT_RATIO * scaleY
}
```

把紧跟其后的 `try { ... } catch { ... }` 改为：`if (!usePassthrough) { try { ... 原逻辑 ... } catch { ... 原 fallback ... } }`，确保 usePassthrough 为 true 时跳过测量调用。

不要改动 `transformed`、text-anchor middle 补偿、multiline 分支、fixedHeight 推断等其他逻辑。
</action>
